# 农事建议数据库实现计划

## 需求分析

用户希望在「诊断分析」页面中建立一个**农事建议数据库**，让各项因子扣分与具体农事建议**自动关联**。

### 核心逻辑
根据算法文档中的 `t_farm_scheme` 表设计：
- **匹配维度**：按「**胁迫因子类型 + 偏离方向 + 生育阶段**」联合匹配农事方案
- **输出内容**：农事措施、执行优先级、复查周期、复查监测指标

### 当前问题
1. 农事建议是**硬编码**在 `plotData[NF-009].suggestions` 中的静态数据
2. 扣分项（deductions）与农事建议（suggestions）之间**没有关联**
3. 不同地块的农事建议完全独立维护，无法复用

## 实现方案

### 一、数据结构设计（农事建议数据库）

在 `diagnosis.html` 中新增 `farmSchemeDB` 全局变量，模拟 `t_farm_scheme` 表结构：

```javascript
// 农事建议数据库（对应 t_farm_scheme 表）
var farmSchemeDB = [
    {
        id: 'S001',
        factorType: '空气湿度',      // 关联胁迫因子
        deviation: '偏高',           // 偏离方向：偏高/偏低
        stages: ['膨大期', '成熟期'], // 适用生育阶段
        priority: 'urgent',         // 优先级
        priorityText: '一级·紧急',
        measures: [
            '立即开启通风设施降湿',
            '树冠喷施代森锰锌 800 倍液预防炭疽病',
            '暂停叶面灌水，避免增加冠层湿度'
        ],
        cycle: '24小时内复查',
        indicators: '空气湿度、叶片病害指数',
        effect: '预计 48 小时内湿度降至适宜区间'
    },
    // ... 更多方案
];
```

### 二、关联匹配引擎

新增 `matchFarmScheme(deduction, stage)` 函数：
1. 输入：扣分项对象（因子名、偏离方向、严重程度）+ 当前生育阶段
2. 匹配规则：
   - `factorType` 匹配扣分项的 `factor` 字段
   - `deviation` 根据 `severity` 和 `phenomenon` 推断
   - `stages` 包含当前生育阶段
3. 输出：匹配到的农事方案数组

### 三、UI 展示改造

#### 3.1 扣分明细表增强
- 每行扣分项增加「**关联建议**」列
- 点击扣分项行，高亮对应的农事建议
- 扣分项与建议之间用颜色/视觉连线关联

#### 3.2 农事建议清单增强
- 每条建议增加「**触发因子**」标签（显示哪个扣分项触发了该建议）
- 建议按「触发因子」分组展示
- 点击建议可高亮对应的扣分项

#### 3.3 新增「农事建议数据库」管理区（可选）
- 展示完整的农事方案库
- 支持按因子类型筛选
- 支持按优先级筛选

## 实施步骤

1. **新增农事建议数据库**（`farmSchemeDB`）
   - 覆盖 6 大维度、20+ 胁迫类型
   - 每个方案包含：因子类型、偏离方向、适用阶段、优先级、措施、复查周期、监测指标、预期效果

2. **实现匹配引擎**（`matchFarmScheme`）
   - 根据扣分项自动推断偏离方向
   - 按因子类型 + 偏离方向 + 生育阶段匹配
   - 返回匹配到的方案列表

3. **改造扣分明细表格**
   - 增加「关联建议」列（显示建议数量，可点击）
   - 点击行时高亮对应的农事建议卡片
   - 添加行 hover 联动效果

4. **改造农事建议清单**
   - 每条建议增加「触发因子」标签
   - 建议按优先级排序
   - 支持点击建议高亮对应扣分项

5. **增强交互体验**
   - 扣分项 ↔ 农事建议 双向联动高亮
   - 数据统计（匹配建议数、覆盖扣分项数）
   - 空状态提示

## 风险与注意事项

1. **数据一致性**：农事建议库需与扣分项因子名保持一致（factorType 必须与 deductions.factor 匹配）
2. **性能**：前端模拟数据量不大，匹配引擎无需优化
3. **可扩展性**：数据库结构预留 `id` 字段，后续可对接后端 API
4. **交互兼容**：确保现有雷达图、因果链等功能不受影响
