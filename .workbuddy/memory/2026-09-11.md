## 南丰蜜桔大数据平台 · 两张分析大屏的配色/字体/地图重构

工作目录：`html/dataanlye/`

### 背景
两张驾驶舱大屏（生长模型 `growth_dashboard.html` / 病虫害模型 `pest_dashboard.html`）存在三类问题：
1. 地图用的是手绘直线多边形，乡镇划分错误且缺 紫霄镇、傅坊乡；
2. 颜色系统混乱：地图用 7 档非单调 visualMap + 红黄绿热力色，与深色青色主题冲突；同一种「长势评分」在地图上是青色、在图表里是红黄绿；
3. 字体依赖 `'DIN Alternate'`（仅 macOS 自带），Windows 上回退到 Consolas，跨机器字形不一致。

### 已完成的改动

**新增文件**
- `data/nanfeng-map.js` — 真实乡镇边界（7 镇 5 乡 + 长红垦殖场 + 南丰工业园区，共 14 个区域），
  来源 `github.com/rooma1989/china_geo_data`（WGS84），坐标简化到 5 位小数，含 `properties.cp` 质心。
- `js/nf-map.js` — 两个大屏共用的地图模块，防止样式漂移。核心导出：
  `RAMP`（单一青色 5 级 `#123A6E→#5AD7F0`）、`scorePieces()/riskPieces()`、`option()`、
  `pointIn()/centerOf()`、`alertMarkerStyle()`、`barColor()`、`rampByRank()`。
  内置 `SHORT_NAME`（长名称缩写）、`LABEL_NUDGE`（标签避让偏移）、`NODATA_FILL`（无数据区中性灰 `#3F4A5C` + 虚线边）。
- `css/fonts.css` — 自托管字体层（单一来源，cockpit-theme.css 不再重复定义 font token）。
- `fonts/` — Noto Sans SC 400/500/700（中文，约 1.1MB/字重）+ Barlow Condensed 500/600/700（数字，约 22KB）。
- `map-style-preview.html` — 地图样式对照预览页。
- `verify-dashboards.mjs` — 回归检查脚本（CSS 合法性 / JS 语法 / 遗留色值 / 依赖引用 / 地图数据完整性）。

**关键设计决策**
- 地图：单一青色系 5 级色阶，**数值由填充深浅表达，色相不承载信息**；描边固定一色；全局发光点收敛到「告警/选中」一处；去掉 3D 投影层、扫描圈、扫描线。
- 图表配色统一规则：**连续型数值（评分/条数/占比）一律单色相按排名取深浅**（`NFMap.rampByRank`）；
  红/橙/黄只保留给状态语义（预警级别、告警）。已应用到乡镇评分、品质趋势、农事建议、识别记录、病害/虫害占比饼图。
- 字体：中文自托管 Noto Sans SC（保证 Windows/macOS/Linux 渲染一致），数字用 Barlow Condensed 替代 DIN Alternate；
  所有数字启用 `tabular-nums` 防跳动；大屏最小字号抬到 12px。
- 对比度：`--ck-text-muted` 由 `#64748b`(3.7:1) 提亮到 `#94a3b8`(6.9:1)，达 WCAG AA。

### 踩过的坑（重要）
- **批量改色必须区分属性**：把 `#fff→rgba(16,40,78,0.85)` 这类替换直接跑全文，
  会把自定义属性名 `--bg-white`、`white-space` 一起改坏（`rgba(...)-space`）。
  正确做法是按声明属性名分别用「文字色表 / 表面色表」，并单次扫描替换（不要多轮级联）。
- 同一轮里**不要并行编辑同一个文件**，会互相覆盖导致部分改动丢失。
- Grep / Read 工具的结果在本会话出现过缓存，与实际磁盘内容不一致；核对最终结果用 PowerShell + `[System.IO.File]::ReadAllText` 或重新运行脚本更可靠。
- Bash 工具在本机不可用（`shim/shell-runtime-bash-env.sh` 报 `dirname: command not found`），全部改用 PowerShell。
- PowerShell 的 stdout 不回显，需要把结果写文件再 Read。
- ECharts map 的 `itemStyle.decal` 斜线填充在本版本不生效；`data` 项 `value:null` 会被丢弃（per-item itemStyle/label 失效），
  改用哨兵值 `-1` 落入 visualMap `outOfRange` 才生效。
- 本机可用的无头浏览器：Edge（`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）、
  Chrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`）。截图命令：
  `--headless=new --disable-gpu --hide-scrollbars --window-size=1920,1080 --virtual-time-budget=20000 --screenshot=out.png url`。
  注意用户可能正在用 Chrome 打开这些页面，**不要杀浏览器进程**。

### 修复：8 个 KPI 弹窗「核心指标 / 详情数据」全空（重要事故 + 防线加固）
用户反馈弹窗数据缺失（举例：在田发生面积分析、活跃病害种类构成——图表正常但下方两块空白）。

**根因**：P0 口径改造时删除了 `alertDataSource.types`，但 `renderModalStats` 的 stats 字面量里
还残留 5 处 `alertDataSource.types.*`。JS 语法完全合法，**求值时抛 TypeError**：
- `openModal()` 内调用顺序是 `renderModalChart` → `renderModalStats` → `renderModalDetails`；
- 图表先渲染成功（所以截图里柱/环图正常、更有迷惑性）；
- `renderModalStats` 抛错后中断，紧随其后的 `renderModalDetails` **根本没执行** → 两块同时空白。
- 又因 stats 是**对象字面量整体求值**，'红色预警' 是最后一个键，一抛就全部失效 → 8 个 KPI 无一幸免。

**修法**：
- stats / details 中的 '红色预警' 改为由 `alertByType` 按 `group` 归并派生：
  病虫害类红色 16+12=28、气象灾害类红色 13，合计 41 = `levels.red`（自洽）；
  details 另加「红色预警最多 = 病害 16 条」「占总预警比 22.3%」，去掉静态的「紧急建议」。
- 顺带清掉 `levels` 注释里对已删除 `types/unclassified` 的过时描述。

**防线加固（verify-dashboards.mjs 新增 3 道）**：
1. `auditDataRefs()` —— 引用键必须 ⊆ 定义键（用 `Object.keys(字面量)` 求定义键，
   内置成员白名单过滤 `filter/map/...`）；同时校验 growth 的 `growthDataSource`。
2. `checkModalCoverage()` —— 每个 `openModal('X')` 入口必须在 `renderModalStats` 与
   `renderModalDetails` 两段里都有 `'X':` 配置。
3. `checkModalRender()` —— 用 `vm` 沙箱真跑渲染函数，逐个入口执行并断言 `innerHTML` 非空、不抛错。
   这是唯一能抓到「运行时抛错」的一层（前两层都是静态）。
4. 辅助函数 `stripComments()`：字符串感知去注释且**长度/换行不变**（行号仍准确），
   避免注释里提到某字段造成误报 —— 第一版就是被我自己写的注释 `alertDataSource.types.*` 误报的。
- 最终结果：`弹窗数据完整性：8 个入口均有核心指标与详情数据` /
  `弹窗渲染实测：8 个入口 × 2 个区块，全部有内容且无异常` / `全部通过`。
