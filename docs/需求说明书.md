## 0 文档使用说明

### 0.1 文档定位

本文档为**基于 HTML 原型逆向编写的需求说明书**，用于描述平台四端（入口 / 后台 / 移动端 / 大屏）的功能范围、字段、交互与业务规则，可作为**功能测试与 UI 测试**的依据。

### 0.2 需求编号规则

每条需求采用统一编号：`REQ-<端>-<模块>-<序号>`。

| 端代码  | 含义                     |
| ---- | ---------------------- |
| `PT` | 应用入口（Portal）           |
| `BH` | 后台管理（Backhand）         |
| `MB` | 移动端（Mobile）            |
| `DS` | 大屏（Dashboard）          |
| `NF` | 非功能性需求（Non-Functional） |

示例：`REQ-BH-ALERT-003` 表示"后台-预警管理-第 3 条需求"。

### 0.3 优先级定义

| 级别     | 含义            | 测试要求            |
| ------ | ------------- | --------------- |
| **P0** | 核心链路，缺失则业务不可用 | 必须 100% 覆盖，回归必测 |
| **P1** | 重要功能，影响主要使用场景 | 必须覆盖            |
| **P2** | 增强/辅助功能，可降级   | 建议覆盖            |

### 0.4 验收标准（AC）说明

每条需求附**验收标准（Acceptance Criteria）**，采用可判定的陈述句，作为测试用例的预期结果来源。

> ⚠️ **重要提示**：文档中出现的具体数值（如"86 分""8.3 万亩""23 条预警""92%"等）均为**原型演示（Mock）数据**，仅用于说明展示形态，**不得直接作为测试预期值**。测试预期值应以真实业务规则与接口返回为准。

### 0.5 本文档的测试适用边界

## 1 项目概述

### 1.1 项目背景

南丰县素有"千年桔都·蜜桔之乡"之称，是全国重要的蜜桔主产区之一。蜜桔产业存在**果园分散、农技推广难、灾情发现晚、品质参差、销售信息不对称**等痛点。县政府希望以"数据底座 + 生长模型 + 病虫害模型"为核心，建设覆盖**农业农村局管理—农技员/农户生产—县级指挥调度**三端的应用平台，实现"统一产业数据底座、面向生长监测、病虫害防控、田间作业、农技服务推广"的产业数字化目标。

### 1.2 项目目标

1. 建立南丰蜜桔全产业链统一数据底座（气象、墒情、视频、品种、虫情、市场价格等）。
2. 提供**生长模型**和**病虫害预测模型**两大核心模型引擎，对单果园长势进行评分诊断、对县域病虫害风险进行时空预测。
3. 构建"县—乡—村—果园—植株"五级预警闭环，形成**采集 → 监测 → 预警 → 处置 → 复查**的责任链。
4. 建设覆盖 PC 端大屏（指挥调度）、后台管理（业务运营）、移动端（农技员/农户生产）的端到端应用入口。

### 1.3 总体架构（前端层面）

项目由四类前端应用组成，**统一产业数据底座**，面向不同角色：

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  生长模型    │  │  病虫模型    │  │  后台管理    │  │  移动端      │
│   驾驶舱     │  │   驾驶舱     │  │   (iframe)   │  │ (农技员/农户) │
│ (dataanlye/  │  │ (dataanlye/  │  │ (backhand/)  │  │ (mobile/)    │
│  growth_…    │  │  pest_…)     │  │              │  │              │
└──────────────┘  └──────────────┘  └──────────────┘  └──────────────┘
                       ▲                    ▲              ▲
                       │                    │              │
                       └──── portal.html 入口导航 ──────────┘
```

### 1.4 用户角色

| 角色        | 主要使用入口      | 关键诉求                      |
| --------- | ----------- | ------------------------- |
| 县级领导      | 两块大屏 / 后台首页 | 看指标、看趋势、看风险、追处置           |
| 农业农村局业务人员 | 后台管理        | 模型管理、预警审核与发布、规则/模板配置、数据治理 |
| 农技员       | 移动端 + 后台    | 数据采集、识图、模型调用、答疑反馈         |
| 种植户/合作社   | 移动端         | 查看自家果园长势、查阅农技资讯、报事报修、销售上报 |

### 3.2 蜜桔知识库（backhand/index.html）

管理蜜桔全产业链业务知识。支持增删改查与多维筛选：

- **品种数据库（variety_db.html）**：管理南丰蜜桔品种（杨小 2-6、蜜广一号、桂月红、桂花蒂系等）。区域维度覆盖市山镇、琴城镇、桑田镇、白舍镇、太和镇、东坪乡等；支持按区域多选（region-checkbox / selected-region-tag）。

- **虫害数据库（insect_db.html）**：虫害知识数据（与病害库共用 schema）。
- **灾害数据库（disaster_db.html）**：气象灾害知识数据（含抗灾指南）。

### 3.3 生长模型（growth/）

#### 3.3.1 模型说明（growth_model.html）

介绍生长模型定位：**用数据读懂果园**，目标"科学种植、精准管理、更好收成"。

核心内容：

- Hero 区：模型适用"已建档果园"；运行流程 "01 选择果园 → 02 读取数据 → 03 运行模型 → 04 查看诊断"；输出综合评分示例（86 / 100，长势状态良好）。
- 模型读取的数据：基础档案（品种、树龄、砧木、栽培方式）；环境长势（温湿度、墒情、果径、叶色）；农事反馈（灌溉、施肥、修剪、处置）。
- 模型设计依据：① 品种与物候特性；② 环境与长势关系；③ 历史结果与反馈（结合诊断、处置、复查记录持续校对）。

#### 3.3.2 模型计算（model_engine.html）

操作型页面，承载具体模型运行：

### 3.4 病虫害模型（pest/）

> 病虫害模型为**多因子耦合时序风险预测模型**，输入向量 `Xt = [Wt, Pt, Dt, It, Ht]`，即气象、物候、病情虫情、虫源基数、历史数据五类因子。

#### 3.4.1 模型说明（pest_model.html）

- 定位：**基于多源数据的智能预测**——融合气象、物候、虫情、历史发生数据。
- 输出维度：多因子 / 耦合 / 时序（14–30 天预测） / 空间（县域多尺度预测）。
- 预测输出：未来 3 天风险、未来 7 天趋势、重点风险区。
- 工作流程：① 数据读取（气象、虫情监测、历史数据）→ ② 因子评分（计算各因子适宜度与权重）→ ③ 耦合预测（多因子耦合与时空预测）→ ④ 输出风险与防控建议。

  - 病虫害预警：红蜘蛛爆发（>30 头/叶，连续 3 天）、锈壁虱（>10 头/视野）、潜叶蛾（新梢受害 > 15%）、炭疽病（病叶率 > 5%）、溃疡病（病叶率 > 3% 台风暴雨后）、粉虱（>50 头/叶）、蚜虫（新梢受害 > 20%）、黑星病（病果率 > 2%）、树脂病（病枝率 > 3%）。
  - 气象灾害预警：高温热害（>38℃ 连续 3 天）、日灼果（果面 > 45℃）、土壤干旱（<25% 连续 5 天）、裂果（>50mm 干旱后突降大雨）、台风（>8 级）、暴雨（24h > 100mm）、冰雹（雷达回波 > 55dBZ）、连阴雨（>7 天）、冻害（<2℃）。
  - 长势异常预警：异常落果（单株 > 10% 连续 2 天）、糖度积累期缺钾（<1.2%）、缺钙（<1.0%）、树势衰弱（叶色黄化率 > 20%）、根系缺氧（<5%）、营养失衡（NPK 比例失衡 > 15%）、叶片早衰（脱落 > 10%）。
  - 品质预警：糖度偏低（<11°Bx 采前 60 天）、果径偏小（<35mm 连续 2 周）、果皮粗皮（>3）、着色不均（色差 > 5）、果实畸形（>5%）。

## 7 跨端业务流程

### 7.1 数据闭环

```
移动端采集（mb_input_*）
       │
       ▼
┌────────────────────────┐
│ 后台审核（manual_collect）│
└──────────┬─────────────┘
           │
           ▼
数据底座（data/* 数据库 + 实时接入）
           │
           ▼
┌────────────────┐    ┌────────────────┐
│ 生长模型 引擎  │    │ 病虫害模型引擎 │
└────────┬───────┘    └────────┬───────┘
         │                     │
         ▼                     ▼
评分与建议 / 风险预测 与预警
         │                     │
         ▼                     ▼
   处方建议推送              预警 / 派工
         │                     │
         ▼                     ▼
移动端 农技员 / 农户     后台审核 → 发布
         │                     │
         └─────── 处置 / 复查 ─┘
                  │
                  ▼
         大屏：处置闭环 KPI
```

### 7.2 预警闭环（标准）

1. **触发**：模型自动生成、人工上报、气象系统导入。
2. **审核**：后台 `alert_manage.html` 通过或驳回；审核人、审核意见留存。
3. **发布**：按 `alert_rule.html` 与 `send_template.html` 选择区域/范围/渠道（系统/短信/邮件）。
4. **处置**：处置记录页面 `dispose_record.html` 跟踪进度；责任人接单、处置、提交证据。
5. **复查**：现场复查，结果回写到大屏与档案。
6. **归档**：预警结束，纳入历史统计与模型校准样本。

### 11.1 预警（alert）状态机

```
                 ┌─────────────┐
   模型/人工/气象 │  待审核      │

                 └──────┬──────┘
                        │ 审核
              ┌─────────┴─────────┐
        通过  ▼                    ▼ 驳回
   ┌─────────────┐          ┌─────────────┐

   └──────┬──────┘          └─────────────┘
          │ 发布
          ▼
   ┌─────────────┐   处置完成   ┌─────────────┐
   │  已发布      │────────────►│  已处置      │
   │ (published) │             │ (disposed)  │
   └─────────────┘             └─────────────┘
```

| 当前状态 | 触发操作    | 目标状态 | 允许角色  | 备注         |
| ---- | ------- | ---- | ----- | ---------- |

| 已驳回  | 编辑后重新提交 | 待审核  | 业务管理员 | 可选         |

## 12 验收要点（建议）

1. **入口门户**：4 张卡片在 PC、平板、手机分别能正确跳转，且无登录污染。
2. **后台登录 → 首页**：4 折叠菜单、Toast、用户菜单正常工作。
3. **知识库六库**：增删改查 + 全文检索 + 多维筛选的正确性。
4. **生长模型**：从模型说明 → 计算 → 诊断 → 报告，形成可视化的评分（86 分级别），并触发对应预警。
5. **病虫害模型**：从参数配置 → 预测 → 风险诊断 → 报告，输出可解释的多因子结果。
6. **预警闭环**：四级别（红/橙/黄/蓝）+ 四状态（待审核/已发布/已处置/已驳回）+ 模板渲染，生成完整可追溯链路。
7. **数据管理**：气象/墒情/视频/价格/外部数据源管理能完整呈现当前设备、当前数据、最近抓取状态。
8. **服务运营**：主体、果园、资讯、人工上报、问题采纳、AI 识别日志的完整闭环。
9. **移动端首页 → 各入口 → 表单提交**：常用的 8 个服务全部可达，提交后能在后台对应列表看到新数据。
10. **两块大屏**：所有 KPI / 图表 / 地图同源、可点击下钻；不存在"两套数字打架"情况；标识了数据口径。
11. **数据采集 → 模型 → 预警 → 大屏 → 处置** 全链路通畅，且各端数据一致、可溯源、可解释。
12. **权限矩阵**：按第 10 章矩阵验证各角色可见/可操作范围符合预期。
13. **状态流转**：按第 11 章状态机验证各对象状态流转正确、非法流转被拒绝。
