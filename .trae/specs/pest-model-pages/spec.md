# 病虫害模型子页面体系 - 产品需求文档

## 概述
- **摘要**: 基于 `pest_model_memo.html` 中描述的"南丰蜜桔病虫害多因子耦合时序风险预测模型"算法，仿照现有生长模型子页面体系，创建病虫害模型的二级菜单和子页面。当前 `pest_model.html` 展示的是10个独立AI图像检测模型列表，需重构为真正的"模型说明"页面，并新增7个子页面覆盖模型的输入、计算、诊断、输出全流程。
- **目的**: 将病虫害预测模型的算法流程（输入数据→因子适宜度→耦合计算→时间累积→虫源/历史/传播修正→概率校准→输出预测）落地为可交互的功能页面，支撑县域尺度病虫害预测工作。
- **目标用户**: 南丰县农业技术员、病虫害预警管理员

## 目标
- G1: 重构 `pest_model.html` 为符合 memo 描述的模型说明页面
- G2: 创建监测数据管理页面，管理模型输入向量 Xt 的5类数据
- G3: 创建模型参数配置页面，管理各病虫害的因子权重、耦合系数、时间窗口等
- G4: 创建预测计算引擎页面，实现7步计算流程的调度与执行
- G5: 创建风险诊断分析页面，展示因子归因、耦合贡献、传播来源追踪
- G6: 创建预测报告页面，展示3天/7天发生概率、风险等级、重点风险乡镇
- G7: 创建模型校准页面，支持历史数据校准与精度验证
- G8: 创建防控方案配置页面，配置病虫害防控建议与优先级
- G9: 更新侧边栏导航，添加所有病虫害模型子页面入口

## 非目标（超出范围）
- NG1: 不修改 `pest_model_memo.html` 的算法说明文档内容
- NG2: 不修改 `disease_db.html`、`insect_db.html` 等数据库页面
- NG3: 不修改生长模型现有子页面
- NG4: 不实现后端API或真实数据存储（纯前端Mock数据）

## 背景与上下文
- `pest_model_memo.html` 详细描述了"南丰蜜桔病虫害多因子耦合时序风险预测模型"的完整算法
- 生长模型在 `html/backhand/growth/` 下有8个子页面，涵盖模型说明、基础档案、因子采集、模型计算、诊断分析、评价报告、数据校准、农事建议配置
- 病虫害模型当前仅有一个子菜单"模型说明"指向 `pest_model.html`，需扩展为完整的子页面体系
- 模型输入向量: Xt = [Wt(气象), Pt(物候), Dt(病情虫情), It(虫源基数), Ht(历史数据)]
- 统一预测公式: Pd(t+h) = Cald,h{ θ1·Σ历史Cd + θ2·Σ未来C̃d + θ3·Id + θ4·Hd + θ5·Spreadd }
- 6种目标病虫害: 红蜘蛛、黄龙病、炭疽病、潜叶蛾、溃疡病、疮痂病

## 功能需求

### FR-1: 模型说明页面 (pest_model.html 重构)
- 展示统一预测公式及8大要素
- 展示6种病虫害的关键因子、主要耦合、时间窗口对比表
- 展示模型核心逻辑流程图
- 展示统计概览（监测区域、病虫害种类、预警数）

### FR-2: 监测数据管理页面 (pest_data.html)
- Tab切换：气象数据、物候数据、病情虫情、虫源基数、历史数据
- 支持按乡镇/日期筛选查看
- 数据录入表单，支持新增/编辑/删除
- 数据可视化图表（趋势图、分布图）

### FR-3: 模型参数配置页面 (pest_params.html)
- Tab切换：因子权重配置、耦合系数配置、时间窗口配置、θ权重配置
- 按病虫害类型分组展示参数
- 参数编辑表单，支持实时保存
- 参数变更历史记录

### FR-4: 预测计算引擎页面 (pest_engine.html)
- Tab切换：计算调度、手动计算、计算日志
- 展示7步计算流程的进度与状态
- 支持单乡镇/批量计算
- 展示每步计算的中间结果

### FR-5: 风险诊断分析页面 (pest_diagnosis.html)
- Tab切换：因子归因、耦合分析、传播追踪
- 主要风险因子排名
- 两因子/三因子耦合贡献分析
- 空间传播来源追踪
- 历史累积影响分析

### FR-6: 预测报告页面 (pest_report.html)
- Tab切换：3天预测、7天预测、历史报告
- 各乡镇发生概率列表
- 风险等级分布（低/中/高/极高）
- 重点风险乡镇列表
- 防控建议清单

### FR-7: 模型校准页面 (pest_calibration.html)
- 历史数据对比（预测值 vs 实际值）
- 模型精度指标（准确率、召回率、F1）
- 参数微调界面
- 校准前后对比图表

### FR-8: 防控方案配置页面 (pest_scheme.html)
- 按病虫害类型配置防控方案
- 方案包含：防控措施、优先级、复查周期、复查指标
- 方案启停状态管理
- 方案版本记录

### FR-9: 侧边栏导航更新
- 在"病虫害模型"一级菜单下添加7个子菜单项
- 菜单项路径指向 `pest/` 目录下的新页面
- 菜单名称与功能对应

## 非功能需求

### NFR-1: 视觉一致性
- 所有子页面采用与生长模型子页面一致的视觉风格
- 使用 Tailwind CDN + Chart.js
- 统一的 content-wrapper 布局
- 统一的 Modal 弹窗样式（max-height: 85vh, 0.3s ease 动画）

### NFR-2: 响应式设计
- 页面在 1200px+ 宽度下正常显示
- 表格支持横向滚动
- 图表自适应容器宽度

### NFR-3: 数据准确性
- Mock 数据需匹配南丰县实际病虫害发生情况
- 乡镇名称使用南丰县12个乡镇
- 病虫害数据符合农业常识

### NFR-4: 代码规范
- 单文件不超过500行
- 使用语义化HTML结构
- 一致的CSS类命名
- 所有操作按钮使用文字标签

## 约束

### 技术约束
- 使用 Tailwind CSS CDN (cdn.tailwindcss.com)
- 使用 Chart.js (cdn.jsdelivr.net/npm/chart.js)
- 纯前端实现，不依赖后端
- 图标使用内联 SVG

### 业务约束
- 病虫害模型为县域尺度预测，不面向单株/单果园
- 模型不读取病虫害图片
- 现有 `pest_model_memo.html` 算法描述不可修改

### 依赖
- 依赖 `index.html` 侧边栏结构
- 依赖 `pest_model_memo.html` 算法描述
- 依赖 `growth/` 子页面的视觉模式作为参考

## 假设
- A1: 南丰县辖12个乡镇
- A2: 6种主要病虫害为红蜘蛛、黄龙病、炭疽病、潜叶蛾、溃疡病、疮痂病
- A3: 模型输入数据可通过物联网+人工采集获取
- A4: 历史校准数据可从农业植保站获取
- A5: 乡镇间传播压力基于邻接关系和主导风向计算
